# 08 里程碑和验收

顺序不能对调。协议和桌面闭环没过验收，就不做手机。每加一个平台只加适配器。

## M0 协议和信令

交付：`jr-proto`、`jr-crypto`、`signal`、两个命令行节点。没有画面。

验收：

- 两台机器用舰队令牌注册，列表能看见对方在线、离线、撤销。
- 邀请、签名临时公钥、会话密钥在日志里能对上。信令进程看不到会话密钥。
- 伪造的无人值守票据被拒绝。
- 包解码有单测：截断、错误版本、重放、未知消息类型。
- 局域网信标能发现对方，并标记局域网。

不做 UI。

## M1 局域网画面和输入

交付：Windows 被控，macOS 主控，原生窗口。一条局域网 UDP。还没有中继。

状态：macOS 被控和主控、原生窗口、局域网 UDP 都在。Windows 那台的适配器写完了
（屏幕枚举、DXGI 采集、Media Foundation 编码、SendInput 注入、ConPTY 终端、
剪贴板、遮挡层、HKCU 自启），整个节点也能对 `x86_64-pc-windows-gnu` 通过类型检查，
但**一次都没在 Windows 机器上跑过**，所以下面这几条验收一条都不算过。
另外采集默认改走 GPU 零拷贝（BGRA→NV12 后交给 MF D3D 设备管理器），
转换链失败才回退 CPU 回读；仍未实机验证。

验收：

- 有线千兆、1080p60、清晰档，端到端 15–30ms。测量方法见媒体文档，至少 3 次，取中位数。
- 拔网线 1 秒再插上，会话恢复或干净失败，不花屏卡死。
- 光标在人为把视频码率打到最低时仍然跟手。
- 键鼠可操作桌面。超过 200ms 的积压输入不会在恢复后补放。
- 空闲时 Windows host 不采集，CPU 平均低于 2%。
- 断开后没有残留注入状态（按键卡住算失败）。

## M2 反向和可靠通道

交付：Mac 也能被控。剪贴板文本、文件传输、终端。Windows 主控。

状态：剪贴板、文件、终端都通。终端跑在 pty 上（`apps/node/src/pty.rs`，
Windows 上走 ConPTY），窗口尺寸变化会真的落到对面的 shell（测试里 `resize 100 40`
之后 `stty size` 回 `40 100`）。收到的剪贴板文本会写进本机剪贴板，`copy` 是反方向。
文件传输测试到 8 MiB，并且验证了进度单调、传到五分之一时取消不留半截文件。
**没有实测 200 MB**。

验收：

- 两个方向都能连。
- 1 MiB 文本剪贴板拒绝并提示，100 KB 文本成功。
- 200 MB 文件双向成功，取消后对端没有半截文件被当成完成。
- 终端能在 Mac 和 Windows 上跑交互命令。窗口尺寸变化对端知道。
- 权限没给时状态是“需授权”，不是连接超时。

## M3 外网

交付：`relay`、打洞、选路、重连、审计。

状态：中继、选路、重连（两条路静默 5 秒就切，2 秒回不来就干净失败）、审计都在。
打洞：节点从信令的 UDP 端口问回自己的公网地址，排进候选列表，并且**持续往对端
每一个候选都发探测包**——只试第一个会在「公网地址打不通、局域网地址能通」
这种常见情形下白等。`apps/node/tests/nat.rs` 有三条：

- 直连候选换成 192.0.2.1（不可达）时，会话仍然靠反射地址在直连路径上建立。
- 候选里放一个诱饵地址，诱饵收得到探测包，说明确实每个候选都发了。
- 一个**用户态模拟 NAT**（只放行自己往外发过的来源）下，两边同时发包才能建路。

这套模拟逼出两个真 bug：会话握手完成后把后续握手包整段丢掉（对面没收到确认时
的重发全被扔，于是单边超时）；以及候选只在第一轮全发。**没有在两台真机上验证过**，
本机证明的是「同时发包 + 反射地址能建路」这条逻辑，不是某个具体 NAT 的行为。

验收：

- 两端都在 NAT 后，打洞成功时不走中继。
- 人为禁掉直连，会话走中继，中继抓包看不到 H.264 起始码明文，也看不到设备公钥。
- 选路在“低 RTT 高丢包”和“高 10ms RTT 零丢包”之间选后者。用网络模拟验证，不靠感觉。
- 中继进程杀掉，5 秒内会话失败或切回路，被控端隐私状态不被留下。此阶段可以还没做隐私屏，但恢复钩子要在，用日志证明 `release_all` 被调用。
- 审计有开始和结束，没有键鼠内容。

## M4 桌面产品面

交付：原生设备列表、授权弹窗、画质档、切显示器、托盘指示、开机自启开关默认关、隐私屏、唤醒。

状态：没有用 Tauri。macOS 设备窗口和观看窗口都有，原生窗口在节点进程内。Windows 设备窗口写在 `crates/jr-host-win/src/desk.rs`（列表、邀请/授权/撤回授权/撤销、已有授权状态、授权弹窗、画质档、开机自启、日志入口），能通过类型检查，**没有在 Windows 上打开过**。托盘菜单和唤醒按钮已经写上，同样没有实机验证。Windows 观看窗口写在 `crates/jr-host-win/src/view.rs`，能通过类型检查，**没有在 Windows 上打开过**；H.264 解码、键盘和滚轮已经接上，但没有真机验收。切显示器的命令行 `display N` 还在。

验收：

- 无人值守票据流程完整。关掉授权后下一秒不能再直接进。
- 隐私屏开启时人站在被控电脑前看不到工作内容。会话结束、host 崩溃重启、主控掉线三种情况，物理屏幕都恢复。
- 睡眠机器在同网有常开节点时代发魔包后能被连上。公网中继单独不能把一台没人醒的电脑叫醒，界面不能暗示能。
- 第二路会话得到“忙”。

## M5 手机主控

交付：Android 和 iOS 主控，同一协议。触摸映射绝对坐标。没有新的包类型，除非 M1–M4 漏了能力位。

验收：

- 蜂窝网络经自己的中继控制家里电脑，代码可辨认，断开干净。
- iOS 安装包里没有被控采集代码路径。
- 手机锁屏再打开，会话按心跳规则恢复或结束，不出现无指示的继续控制。

## M6 Android 被控

交付：前台服务、录屏授权、输入注入、文件和剪贴板。

验收：

- 授权存在时，另一台设备能看能点。
- 重启后状态变为“需重新允许录屏”，不会静默采集。
- 通知栏始终有“正在允许被控”。用户划掉通知或停止服务，会话结束。
- 不使用无障碍以外的隐藏注入手段。

## M7 Linux

交付：无桌面终端和文件先过。桌面采集作为该里程碑后半，失败就保持仅终端，不阻塞发版。

验收：

- 一台没有显示器的 Linux 在列表里是“仅终端”，能完成 shell 和文件。
- 有桌面且门户允许时能看画面。Wayland 注入失败时明确降级成观看或仅键盘，不假装能点。

## 跨里程碑的发布门槛

任何一版给所有者每天用之前：

- 协议主版本协商有测试。
- 隐私恢复有崩溃测试。
- 中继抓包抽查过密文。
- 已知限制写在版本说明里：iOS 不能被控，Android 不能开机即被控，登录前安全桌面不能控，HDR 没有。

## 风险

| 风险 | 应对 |
|---|---|
| macOS 虚拟显示器 API 行为随系统变 | 隐私屏可以降级，但必须告知，不能假成功 |
| 硬编 4:4:4 在部分显卡不可用 | 能力查询，自动 4:2:0，界面写“此设备无法真彩” |
| 打洞在对称 NAT 上失败 | 中继是正式路径，不是异常 |
| 输入注入在部分游戏被反作弊拦截 | 不当成远控故障去绕过反作弊。文档写明不支持 |
| 范围膨胀成商业远控 | 非目标列表有效。陌生人协助、计费、隐藏模式都不做 |
| 实现时想抄现成协议省时间 | 评审时对照 D1。包格式不同源、不同魔数、不同握手才算自研 |

## 第一版完成的定义

M0 到 M5 完成，M4 的隐私屏至少在 Windows 上达到验收，Mac 允许降级但要讲真话。M6、M7 可以紧随，不挡“所有电脑 + 手机主控”这件事。

Android 被控和 Linux 桌面没做完时，不能对外说已经覆盖全部设备。设备列表必须把没做完的平台显示成真实能力，而不是先放一个失败按钮。
