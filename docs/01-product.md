# 01 产品规格

## 1. 产品定义

Jaryn Remote 是给同一所有者用的远控。目标是：人在任意一台自己的设备上，控制其余已经配对、并且操作系统允许被控的设备。

它不是游戏串流专用工具，也不是企业 IT 托管桌面。游戏低延迟管线是实现手段。办公、看代码、传文件、开终端、临时看一眼手机，走同一条会话。

所有者自己部署信令服和中继，或者在一台常开的自己的机器上跑这两个进程。不依赖第三方远控厂商的账号、节点或协议。

这一份是产品规格，不是验收报告。代码已经做到哪、哪几条还没在真机上证明，写在仓库根目录的 README。界面和命令行上的四档名字是「清晰 / 均衡 / 高帧率 / 省流量」，对应下面表里的清晰、均衡、游戏、省流。编号仍是 1 到 4。

## 2. 用户和设备假设

第一版按一个所有者、一个设备舰队设计。数据模型从第一天带 `account_id`，方便以后加第二个人，但界面不做团队管理。

默认舰队：

| 设备 | 角色 |
|---|---|
| macOS 电脑 | 主控 + 被控 |
| Windows 电脑 | 主控 + 被控 |
| Linux 有桌面或无桌面 | 被控为主；有界面就能主控 |
| Android 手机 / 平板 | 主控 + 有限被控 |
| iPhone / iPad | 仅主控 |

没有列出的设备（电视、游戏掌机、浏览器）不进第一版。浏览器里看画面意味着把解码和输入放进 WebView，和延迟目标冲突。

## 3. 能力矩阵

主控必须按被控端声明的能力显示动作，禁止出现一个点了没反应的“控制”按钮。

| 能力 | Windows | macOS | Linux 桌面 | Linux 无桌面 | Android | iOS |
|---|---|---|---|---|---|---|
| 被控画面 | 是 | 是 | 第二阶段 | 否 | 是，重启后要重新授权 | 否 |
| 键鼠 / 触摸注入 | 是 | 是 | 第二阶段，Wayland 可能只能键盘 | 否 | 是，需用户打开注入授权 | 否 |
| 主控 | 是 | 是 | 是 | 不需要 | 是 | 是 |
| 声音回放 | 是 | 是 | 第二阶段 | 否 | 是 | 仅作为主控接收 |
| 麦克风回送 | 协议预留，第一版不做 | 同左 | 同左 | 否 | 同左 | 同左 |
| 文件 | 是 | 是 | 是 | 是 | 是 | 主控可传，不能被控 |
| 剪贴板 | 文本，上限 1 MiB | 同左 | 同左 | 同左 | 文本 | 主控可收发文本 |
| 终端 | 是 | 是 | 是 | 是，这是无桌面机器的主路径 | 否 | 否 |
| 无人值守 | 是 | 是，权限仍须事先授予 | 是 | 是 | 否，录屏授权不能跨重启 | 不适用 |
| 隐私屏 | 有虚拟显示器时是 | 有虚拟显示器时是 | 后做 | 不适用 | 否，用系统自带的“正在投屏”通知代替 | 不适用 |
| 远程开机 | 局域网魔包，或同网常开节点代发 | 同左，硬件要支持 | 同左 | 同左 | 否 | 否 |

iOS 被控明确不做。系统不提供“后台采集整个屏幕并注入触摸”的第三方接口。主动开始的屏幕广播也不做，避免做出一个半成品被控端让人误以为手机能被控。

Android 被控做得到，但做不到 PC 那种开机即被控。MediaProjection 授权跟本次进程绑定，重启或被系统杀掉就失效。被控时必须有一条用户能看见的前台通知。这是系统要求，也是产品要求。

## 4. 核心场景

### 4.1 从手机控制家里的电脑

手机和电脑都已注册。电脑睡眠或锁屏都可以在线（进程还在）。用户点设备，电脑若开了对该手机的无人值守授权，直接进会话；否则电脑弹出允许，手机等待。画面出来后可以键鼠、剪贴板、传文件。

### 4.2 两台电脑互控

Mac 控 Windows，或反过来。局域网时不经过中继。外网时先打洞，路径差再走自己的中继。

### 4.3 无桌面 Linux

设备列表里显示“仅终端”。点进去是终端，不是黑画面。有文件通道。

### 4.4 看自己的 Android

手机事先开过被控并完成录屏授权。另一台设备能看能点。授权丢了，列表状态是“需要在手机上重新允许”，不是“离线”。

### 4.5 隐私

人离开自己的 Windows/Mac 时打开隐私屏。物理屏幕不显示正在被看的内容，采集仍继续。会话结束、崩溃或心跳丢失，必须恢复物理显示和本地输入。卡住黑屏算故障，不是特性。

### 4.6 观看

同一条会话把输入关掉就是观看。第一版一台被控同时只接受一个会话。第二个请求得到“忙”，不抢占。

## 5. 画质档

用户看到四档，不看到编码器参数。

| 档位 | 用途 | 起点 | 上限 | 帧率 | 色度 |
|---|---|---|---|---|---|
| 清晰 | 代码、文档 | 8 Mbps | 30 Mbps | 最高 60 | 编码器支持则 4:4:4，否则 4:2:0 |
| 均衡 | 默认 | 8 Mbps | 20 Mbps | 最高 60 | 4:2:0 |
| 高帧率（规格草稿叫过「游戏」） | 动态画面 | 16 Mbps | 50 Mbps | 最高 120，面板不支持就 60 | 4:2:0 |
| 省流量（规格草稿叫过「省流」） | 蜂窝 | 1.5 Mbps | 4 Mbps | 最高 30 | 4:2:0 |

自适应只在该档上限内调节。用户锁定码率时仍允许丢帧保延迟，不允许把延迟堆进缓冲区换清晰。

第一版只做 SDR。HDR 作为能力位留着，恒为 0。

## 6. 会话里用户能做的事

- 看被控画面，指针在本地合成，不跟视频帧走。
- 键鼠。游戏里相对鼠标，桌面里绝对坐标。
- 切换显示器。第一版一次看一块屏，切换不断开会话。
- 切换画质档。
- 打开或关闭隐私屏（被控端能力允许时）。
- 传文件，双向，可取消。
- 剪贴板文本同步，会话内手动触发，不静默后台监听所有复制。
- 打开终端（能力允许时）。
- 断开。

协议预留、第一版界面不做：手柄、麦克风回送、多画面并排、多人观看、会话录像。

## 7. 设备列表要表达的状态

状态必须可区分，禁止都叫“离线”：

| 状态 | 含义 |
|---|---|
| 在线 | 信令心跳正常，能发起会话 |
| 局域网 | 在线且本机刚收到信标，优先直连 |
| 需授权 | 进程在，但屏幕录制或注入权限没了 |
| 需重新允许录屏 | Android 专有 |
| 睡眠可唤醒 | 信令不见了，但同网有节点能发魔包，且登记过 MAC |
| 忙 | 已有会话 |
| 版本不合 | 协议主版本不同 |
| 已撤销 | 所有者把这台设备移出舰队 |
| 离线 | 以上都不是 |

## 8. 权限和无人值守

被控端第一次被连，必须有人在本机点允许。允许只对这一台主控、这一次有效。

“允许这台设备以后直接控制”会生成一张由被控端私钥签名的授权，不是信令数据库里的一个布尔值。关掉开关或撤销设备，授权立刻失效。

无人值守不等于隐藏。被控端会话期间要有可见指示：菜单栏图标、托盘图标，或 Android 前台通知。不提供隐藏图标、不提供“对方不知道被控”的模式。

开机自启是显式设置，默认关。

## 9. 体验要求

这些数字是验收线，不是宣传语。端到端指被控端屏幕内容变化，到主控端像素画出来。

| 条件 | 要求 |
|---|---|
| 有线局域网，1080p60，清晰档 | 端到端 15–30ms；超过 40ms 不算过关 |
| 同城宽带，走自己的中继 | 50ms 内可用；短时抖动不把缓冲堆过 50ms |
| 光标 | 位置更新不跟视频帧绑定；视频卡一下时指针仍跟着本地移动 |
| 输入 | 超过 200ms 的输入事件直接丢，不补放 |
| 断开恢复 | 路径闪断 5 秒内重连；超过则结束并释放隐私屏 |
| 空闲占用 | 不被控时主机进程 CPU 平均低于 2%，不采集、不编码 |
| 失败可见 | 打洞失败、权限缺失、版本不合，都有单独文案 |

不承诺 5ms。那种数字通常只是网络 RTT，不是屏幕到屏幕。

## 10. 非目标

- 不控制 iOS，不做 iOS 屏幕广播。
- 不远程协助陌生人，不做一次性分享码给任意第三方。第一版只有已注册进同一舰队的设备。
- 不录像、不上传画面、不把键鼠内容写入审计。
- 不绕过系统权限弹窗，不做免杀，不做隐藏驻留。
- 不自研 H.264/H.265 编码器，不自研加密算法。
- 不兼容别人的远控协议，因此也不能当那些产品的客户端。
- 不做商业节点调度、计费、多租户后台。
- 不在第一版做登录画面之前的 Windows 安全桌面控制。用户会话里的远控先做完。登录前控制要单独的系统服务，列入以后的显式功能，默认关。

## 11. 成功标准

所有者用自己的手机，在蜂窝网络上，通过自己的信令服，控制自己家里已授权的 Windows 或 Mac：能看清代码、指针跟手、能粘贴一段文本、能传一个文件、断开后家里屏幕恢复。全程没有调用任何第三方远控程序。
