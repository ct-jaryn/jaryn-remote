# 04 媒体和输入管线

本文规定会话里字节以外的时间行为。包格式在协议文档。这里改了而不改验收，视为没改。

## 1. 延迟预算

端到端 = 被控端像素发生变化，到主控端屏幕画出这个变化。包含采集、编码、发送排队、网络、抖动缓冲、解码、合成。

| 段 | 局域网预算 | 超了怎么办 |
|---|---|---|
| 采集 | 1–2ms | 检查是否拷到了 CPU，或采集超时设得太大 |
| 编码 | 3–8ms | 确认无 B 帧、缓冲只有一帧、没有软件编码 |
| 发送排队 | < 2ms | 发送队列超过 3 帧必须丢 |
| 网络 | 1–5ms 局域网 | 不是软件能压的部分，单独记 |
| 抖动缓冲 | 0–8ms，上限 50ms | 禁止默认 100ms 缓冲 |
| 解码 + 上屏 | 3–8ms | 硬解，mailbox 呈现，不等垂直同步排队两帧 |
| 合计 | 15–30ms | M1 验收线 |

键鼠不在这条合计里。键鼠从主控采样到被控注入，局域网目标低于 10ms，并且不看视频缓冲。

## 2. 时钟

各方维持自己的单调钟。会话时钟零点是进入 `keys_ready` 的本地单调时间。包里的 `timestamp_us` 是相对这个零点的微秒。

RTT：

```text
主控每 200ms 发 Ping，timestamp = 主控会话钟
被控立刻回 Pong，echo 该 timestamp，并带被控会话钟
rtt = 主控现在 - echo
```

不做全网时钟同步。端到端估计用可选的捕获时间戳：

```text
控制器收到帧的本地时间 - (对方 timestamp 换算)
```

换算只用于统计，不用于决定是否丢帧。丢帧只看本机到达顺序和 frame_id。

开发期测量端到端用外部手段：被控端屏幕放一个每 100ms 变色的窗口，主控摄像头或光敏探头不在软件验收里。软件验收用“已知的捕获时间戳 + 主控 present 回调时间”，并在文档里承认它不含面板扫描。M1 可以用高速拍摄作为一次人工记录，之后回归用软件估计，阈值放宽到 40ms 就失败。人工记录的目标仍是 30ms。

## 3. 采集

只采集用户选中的那一块显示器。不采集整个虚拟桌面再裁剪，否则多屏机器白编码。

采集循环：

```text
loop:
  frame = source.poll(2ms)
  if timeout: continue
  if frame 只是指针形状变化: 交给光标通道，不编码
  encode_slot.store_latest(frame)   # 容量 1
```

`poll` 超时 2ms 是为了能在停止会话时尽快醒来。不使用无限等待。

第一版允许每帧都是全帧。脏矩形优化不进协议，避免和硬编全帧路径打架。桌面静止时编码器输出应很小。如果静止画面码率仍顶满上限，算编码器参数错误，不是网络问题。

显示器信息在 Capability 里给出原点、物理像素尺寸和缩放。主控用物理像素映射输入。不使用 DIP 坐标穿过网络，否则 Windows 缩放 150% 时点击会偏。

分辨率或缩放变化：采集端发新的 Capability，然后强制 IDR。主控重建解码器和坐标变换。旧帧丢弃。

## 4. 编码参数

调用硬件编码器时必须设置的意图，API 名字各平台不同，意图相同：

| 项 | 值 |
|---|---|
| 编码 | 优先 H.264。能力位有 H.265 且画质档是游戏时可用 H.265。第一版默认 H.264，少一个跨设备解码变量 |
| 档次 | 4:2:0 用 High。4:4:4 仅当 `encoder_caps` 声明支持，并且画质档是清晰 |
| B 帧 | 0 |
| 重排延迟 | 0 |
| 码控 | CBR |
| GOP | 不按固定短 GOP。至少每 2 秒一个 IDR，此外仅在请求、切显示器、重置时出 IDR |
| VBV / 缓冲 | 不超过 `bitrate / 8`，也就是约 125ms 的上限，能更小就更小 |
| 切片 | 编码器若支持多切片，设 4 片，便于一片一包。不支持就由我们在码流层按 1160 字节切，切在 NAL 边界 |
| 参数集 | 每个 IDR 前带 SPS/PPS。另外每秒重复一次，防中途丢参数集 |
| 低延迟开关 | 平台 API 若有“低延迟 / 无超前”标志，打开。没有就靠 B 帧 = 0 和一帧缓冲保证 |

软编只允许在没有任何硬件编码器时启用，并且 Capability 的一个实现侧标志要让 UI 写“此设备正在软件编码，延迟会高”。软编不是第一版验收路径。M1 的 Windows 机器必须有硬编。

码率由 JCC 每 200ms 更新一次。见协议文档。编码器重置视为一次 IDR，不视为新会话。

## 5. 发送

一个编码帧到来后立刻切片发送，不等下一帧。

发送队列最多 3 个未发送完的帧。新的 IDR 可以挤掉队列里所有非参考帧。队列里已有更新的 IDR 时，更旧的帧全部丢弃。

FEC 校验包在本组数据片发出后立即发出，不攒到定时器。

发送线程使用测得的目标码率做平滑。突发不允许超过 2 毫秒的线路时间。平滑是为了不把家用路由器的队列打满，不是为了多缓冲。

## 6. 接收、重组、呈现

主控视频重组器：

- 按 frame_id 组装。
- 收齐则送解码。
- 200ms 未收齐，丢帧。参考帧则请求关键帧。
- 已呈现过的 frame_id 之后又来更小的 frame_id，丢弃。路径切换时允许一次时间戳回跳，回跳那一帧丢弃，不倒退画面。

抖动缓冲：

```text
target_delay_ms = clamp(2 * jitter_ms, 0, 50)
```

初始 `jitter_ms` 按 0。也就是第一个能解的帧立刻上屏。不要预滚。

解码队列深度目标是 0 或 1。Feedback 里的 `decode_queue` 大于 1 时，JCC 视为拥塞，即使丢包为 0。这能抓住“网络还行但主控解码堆帧”的情况。

呈现用 mailbox：只保留最新一帧。垂直同步如果会再引入一帧等待，桌面档可以等，游戏档不等。M1 先不等待垂直同步，接受撕裂，不接受加帧。撕裂若不可接受，再在游戏档单独开一个开关，默认关。

## 7. 光标

被控端光标位置每变化一次就发 CursorPos，最高 250Hz，超过则合并。不跟视频帧率对齐。

形状变化走可靠通道。主控在 present 时把最新光标画在画面上。视频卡住时，光标层仍随 CursorPos 更新。这是“跟手”的定义，M1 必须能演示：把码率人为降到 500 kbps，移动鼠标，指针不呈幻灯片。

被控端系统光标可以保留，也可以在会话中隐藏。隐藏不是隐私。隐私靠虚拟显示器方案。主控必须画自己的光标层，否则隐藏被控光标后用户什么都看不见。

相对鼠标模式时，CursorPos 仍发送，但主控可以隐藏系统光标并抓获指针。模式由被控端决定：进入独占全屏或指针被应用抓获时，发 SessionControl 的一个 flag，主控切到相对移动。第一版如果检测独占不可靠，允许用户在会话里手动切“游戏指针”。协议已经有相对移动种类，不需要新消息。

## 8. 输入注入

注入线程看到事件就调用平台 API，不加定时器去“平滑”。

坐标：

```text
主控显示矩形内的指针位置
  -> 换成该显示器物理像素
  -> 加上 Capability 里的 origin_x/y
  -> 绝对移动事件
```

不在主控端做“预测补偿”。预测会在办公点击时点错。

按键注入后登记按下集合。集合里的键若 500ms 没有抬起，注入抬起。鼠标键和触点不套这个 500ms，持续拖动会保活，30s 没有更新才兜底释放；会话结束时清空集合并抬起。

不记录输入日志。调试日志最多记 kind 和 event_id，不记坐标序列的长期存盘。开发开关可以在内存里留 2 秒，默认编译关闭。

## 9. 音频

采集本机播放回环，不是麦克风。编码 AAC-LC，48 kHz，1024 样本，约 21ms 一帧。这是系统编码器的帧长，接受它比视频预算更松。

播放端音频缓冲目标 40ms，上限 80ms。超过就丢音频帧赶上，不让声音把画面拖住。画面和声音允许短暂对不齐，优先画面延迟。

被控端喇叭在隐私模式下静音。没有隐私模式时不静音，避免所有者在本机时突然没声音却不知道原因。会话开始若要静音，必须是隐私动作的一部分，不能是连接的副作用。

麦克风回送不在第一版。协议 feature bit 2 恒为 0。

## 10. 画质档到编码器

| 档 | 分辨率 | 帧率上限 | 色度 | 起点码率 | 上限 |
|---|---|---|---|---|---|
| 清晰 | 不放大，最高边长 3840 | 60 | 能 4:4:4 就用 | 8 Mbps | 30 Mbps |
| 均衡 | 最高边长 1920 | 60 | 4:2:0 | 8 Mbps | 20 Mbps |
| 游戏 | 最高边长 1920 | 120 | 4:2:0 | 16 Mbps | 50 Mbps |
| 省流 | 最高边长 1280 | 30 | 4:2:0 | 1.5 Mbps | 4 Mbps |

源分辨率低于上限时不放大。缩放在采集端完成，用显卡缩放，不在主控端放大一个糊帧来假装清晰。

切换画质档允许编码器重建。重建期间主控保持最后一帧，超过 500ms 没有新帧才显示“正在调整画质”。

## 11. 背压

只允许在这些点丢数据：

| 位置 | 丢什么 | 不丢什么 |
|---|---|---|
| 采集槽 | 未编码的旧帧 | 不丢光标形状 |
| 发送队列 | 非参考视频帧 | 不丢可靠控制 |
| 视频重组 | 超时帧 | 不因此断开，除非参考帧请求也失败并超过重连时间 |
| 输入队列 | 过期移动 | 不丢未配对的键抬起；抬起见 500ms 规则 |
| 音频 | 超出 80ms 的旧音频帧 | 不倒放 |

可靠流窗口满时，文件暂停，输入不受影响，因为输入不是可靠流。

## 12. 失败时的画面

解码失败：保持上一帧，请求关键帧。连续 1 秒没有成功帧，画面上显示“画面中断，正在恢复”，会话状态仍是 Streaming，直到 `SESSION_DEAD_MS`。

不要在单个花帧时断开。也不要无限显示冻结画面却不告诉用户。1 秒是这条分界。
