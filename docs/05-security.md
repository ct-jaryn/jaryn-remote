# 05 身份、授权和威胁模型

## 1. 要保护什么

| 资产 | 要求 |
|---|---|
| 画面、声音、键鼠、剪贴板、文件、终端内容 | 网络和中继不能读 |
| 无人值守授权 | 信令不能伪造“这台电脑允许那台手机控制” |
| 舰队成员 | 没有令牌的设备不能注册 |
| 本机使用者 | 必须能知道正在被控，必须能一键断开，会话结束后屏幕和键盘恢复 |
| 审计 | 能回答谁在何时连过谁，不能变成键鼠记录器 |

不保护：所有者自己的信令服务器被完整攻破后的在线关系。攻破信令能看到谁在线、谁邀请谁。不能看到画面，也不能签出新的无人值守票据。若攻破的是设备本身，远控软件不再有边界，这不在威胁模型里假装能防。

## 2. 密钥

每台设备首次启动在本机生成 Ed25519 密钥对。当前桌面实现将设备私钥（`device.pkcs8`）与注册凭据以仅当前用户可读写的权限（Unix `0600` / 目录 `0700`）保存在本机数据目录中；后续演进目标是接入各操作系统的原生密钥库（Windows DPAPI、macOS Keychain、Android Keystore、iOS Keychain）。不上传私钥，不支持从云同步私钥，换机器就是新设备。

信令服务器有自己的 TLS 证书与身份。第一版设备通过 TLS 证书 SHA-256 指纹钉扎（Pinning）验证信令：首次连接配置或确认证书指纹后落盘钉住；以后证书变了就拒绝连接并报“服务器身份变了或 TLS 失败”。不做公共 CA 体系也能安全运行。若所有者轮换了服务器证书，需要在设备上更新指纹，这个麻烦是有意的。

设备向信令注册支持两种鉴权模式：

1. **舰队令牌模式（默认）**：信令首次启动生成 32 字节随机舰队注册令牌，只打印一次，数据库仅存 `SHA-256(token)`。设备注册时用设备私钥对令牌与公钥签名。令牌泄漏即可轮换：旧哈希作废，已注册设备靠自身公钥继续在线不掉线，新设备不能再用旧令牌。
2. **封闭配对模式（`--private`）**：服务器不设共享注册令牌，默认拒绝一切未登记公钥。每条 TLS 连接由服务器下发一次性 32 字节随机挑战（`AuthChallenge`），节点用本机 Ed25519 私钥签名应答；首次加入须所有者在本机/SSH 临时开启 10 分钟单设备配对窗口并核对 8 位码批准（详见 `docs/09-private-pairing.md`）。

信令不可用时的局域网配对见服务器文档。信任只来自两种结果：曾经完成过签名会话，或用户在两端目视核对过 6 位码之后的签名交换。看到信标不等于信任。配对码不构成无人值守票据。

## 3. 会话密钥

流程的规范在协议文档第 5 节。安全要求是：

- 临时 X25519 私钥用完即丢，不落盘。
- 媒体密钥不经过信令。信令只转发签名过的临时公钥。
- 派生盐包含双方签名，临时公钥被替换而签名不匹配时，验签失败。
- 每个方向一把密钥。
- packet_seq 不复用，接收窗防重放。
- 会话结束丢弃媒体密钥。不支持会话恢复时复用旧密钥。重连若还在 `RECONNECT_MS` 内且进程没死，可以继续用当前密钥。超过就新邀请、新密钥。

不自研分组密码、不自研签名、不实现“私有扰码”。加密库限定在 `ring` 或 `aws-lc-rs` 之一，实现时选一个写进 `jr-crypto` 的模块注释，不两套混用。

## 4. 授权

### 4.1 当场允许

被控端弹出本机窗口：对方短号、设备名、请求的能力（看画面、控制输入、文件、终端）。默认只勾选看画面和控制输入。文件和终端要另勾。用户点允许后，被控端才发 InviteDecision。

这个窗口必须在被控端操作系统的桌面上，不能只在主控端显示“已请求”。没有桌面的 Linux 用本机终端提示；若没有人值守且没有票据，拒绝，原因 `unauthorized`。

### 4.2 无人值守票据

用户在被控端打开“允许该设备以后控制”后，被控端签署：

```text
assertion = host_sign(
  ASCII "JRP-GRANT1" ||
  host_device_id ||
  controller_device_id ||
  feature_bits_u32 ||
  not_before_unix_u64 ||
  not_after_unix_u64
)
```

信令只存储断言字节，邀请时转给被控端自己验，也转给主控做展示。验签用本机私钥对应的公钥，不信任信令说“已授权”。

关闭开关时，被控端签署一张 `not_after = 现在` 的新断言覆盖，并删除本机旧断言。信令上的旧断言即使还在，被控端本地状态也拒绝。以被控端本地为准。信令上的副本只为了多设备展示。

票据最长一年。过期必须再点一次。不自动续期。

### 4.3 撤销

所有者在任一已登录节点把设备撤销。信令广播 Revoke。被撤销设备删除会话并拒绝新邀请。它的私钥仍在本机，但服务器不再接受这个公钥的心跳。重新加入需要新的注册令牌流程，并且生成新密钥，避免撤销后又被旧密钥复活。实现上：撤销后该公钥进入拒绝列表，即使拿着令牌也不能再用同一公钥注册。用户要“重新添加这台电脑”时，本机生成新设备密钥。界面把这件事说清楚。

## 5. 指示和断开

会话存续期间：

- 桌面：托盘或菜单栏有持续图标，点开能断开。
- Android：前台服务通知，点停止即断开。
- 无桌面 Linux：syslog 加一个本地套接字，所有者可以用命令断开。

不提供关闭指示的设置。

本机键盘的断开热键：Ctrl+Alt+Shift+Q（macOS 为 Control+Option+Shift+Q）。热键在节点进程注册，不依赖窗口是否打开。热键冲突时允许用户改，但不能删掉最后一个断开办法。

## 6. 隐私屏

隐私屏是显示路由问题，不是在画面上盖一层黑色窗口。盖在同一块被采集的屏幕上，采集到的就是黑的，远控也废了；若黑色窗口不在采集范围内，本机人仍可能从另一路径看到。

可接受的实现只有：采集源是一块虚拟显示器，物理显示器不显示这块虚拟显示器的内容。做不到时，SessionControl 返回拒绝，界面讲真话。

进入隐私模式前把显示拓扑写到恢复文件。以下任一情况都要读恢复文件并还原：

- 正常 Bye
- 心跳死亡
- host 启动时发现恢复文件还在
- 操作系统注销通知

还原失败要在本机留下可见错误，不要只写日志。用户面对黑屏时，托盘如果还在，必须有“恢复屏幕”按钮。热键同样调用恢复。

## 7. 输入和剪贴板的额外约束

- 不把键鼠、剪贴板、文件名写入审计和长期日志。
- 剪贴板只在会话窗口聚焦时从主控发出。被控端不后台监听本地复制来同步。
- 终端不提权，不附着到已有系统会话。
- 不采集密码管理器的安全输入框作为特殊通道。采得到的屏幕像素由操作系统决定。macOS 的安全输入我们不绕过。

## 8. 威胁

| 威胁 | 处置 |
|---|---|
| 同一局域网的人看 UDP | 媒体是 AES-GCM，没有密钥只能看到包长和路由令牌 |
| 中继运营者看包 | 同上。中继没有私钥 |
| 恶意信令替换临时公钥 | 签名验不过，握手失败 |
| 恶意信令伪造无人值守 | 断言签名验不过 |
| 重放旧的 UDP 包 | seq 窗口 |
| 重放旧邀请 | session_id 一次性，票据有期限，且被控端拒绝正在进行以外的旧 session |
| 偷走注册令牌 | 能注册新设备，不能控制已有设备。所有者应能看到新设备并撤销。新设备注册时，已在线节点收到 Presence，界面提示“新设备加入” |
| 偷走一台已授权手机 | 能控制授予过的电脑。缓解：本机热键、撤销、票据过期、手机本身有系统锁屏。远控软件不替代设备锁屏 |
| 会话中主控恶意不发送断开，并保持隐私黑屏 | 心跳死亡后被控端自己恢复。不依赖主控善意 |
| 通过本软件做未授权控制 | 不是产品功能。没有陌生人分享码，没有隐藏模式，没有权限绕过 |

新设备加入的提示是舰队安全的关键界面，不是装饰。M0 就要在协议层有 Presence 事件，M4 必须做成用户看得见的提示。

## 9. 审计

服务器记录：

```text
audit_id
controller_device_id
host_device_id
started_unix_ms
ended_unix_ms
end_reason
path_id                  # 结束时的路径
bytes_to_host
bytes_to_controller
feature_bits             # 实际开启过的能力
```

不记录 IP 的长期档案可以再议。第一版记录连接时的地址，保留 30 天，用于排障。不记录包内容。

被控端本地同样记一份会话开始和结束，防止信令被删日志后本机毫无痕迹。本地记录不含地址以外的内容。

## 10. 不做的安全把戏

- 不把加密当混淆。不对抗逆向自己的客户端。
- 不检测虚拟机来拒绝运行。所有者的设备可能就是虚拟机。
- 不扫描局域网其他人家的设备。信标只匹配已在舰队中的 device_id。
- 不在日志里打印令牌、私钥、会话密钥、剪贴板。
