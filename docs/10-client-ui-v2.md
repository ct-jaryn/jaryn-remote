# macOS 客户端：链路台（Link Deck）

设计图：[SVG](../assets/client-ui-v2.svg) · [PNG](../assets/client-ui-v2.png)（设备窗口、观看窗口、软件遮挡层三张）

## 设计方向

一个界面只回答两个问题：这台机器是谁，到对面那台机器的链路通不通。

- 侧栏是舰队定位：品牌标记、搜索、按「可连接 / 其他」分组的设备行；本机身份和服务器连接状态固定在底部，翻列表时不动。
- 主区是单设备聚焦：本机身份顶栏（固定放日志、屏幕权限）、会话横幅、设备链路面板、一个主要动作、最近动态。没有设备时显示居中的引导空状态，而不是空卡片网格。
- 视觉记忆点来自产品自己的图标：两块相连的屏幕加一笔青绿色的 J。取它的青绿作「链路色」（亮色约 #0A8FBA，暗色约 #5CD8F5），薄荷色只用在选中条与标记渐变上。
- 刻意避开这类产品常见的模板感：没有紫蓝渐变、没有满屏光晕、不用玻璃卡片堆叠、不写空泛大标题、不铺重复卡片网格。

仍然只用原生 AppKit 和系统材质，Rust 继续负责设备状态、会话与诊断；不增加网页运行时，不新增依赖。

## 视觉语言

- 颜色一律用 `NSColor` 动态色，明暗外观由系统解析；分隔线用 `NSBox` 的 separator，外观切换不需要重算颜色。
- 机器身份（设备短号、信令地址）一律等宽字，短号写成 `A1B2 · C3D4`；正文用系统字体。
- 状态由形状、颜色和文字三重表达，不靠颜色单独承担信息：

| 状态 | 字形 | 颜色 |
|---|---|---|
| 在线 | 实心点 | 系统绿 |
| 局域网 | 实心点 + 外圈 | 系统绿 |
| 忙（会话中） | 空心环 | 链路色 |
| 需授权 / 需重新允许 / 系统安全提示 | 空心点 + 感叹 | 系统橙 |
| 已撤销 | 空心点 + 斜杠 | 系统红 |
| 仅终端 | 小方块（终端造型） | 次级文字色 |
| 离线 | 细空心圈 | 次级文字色 |

### 设备链路条

本机 → 信令服务器 → 目标设备。节点用产品图标里的屏幕造型（带一条底边），两段连线中间留白给 leg 文案：前一段写「已连接 / 未连接」，后一段写「直连 / 局域网直连 / 经服务器」。信令断线时中间节点的数值转成橙色，和「设备离线」区分开。

### 选中与悬停

设备行整行自定义绘制：选中是左侧一条链路色渐变竖条加 14% 链路色底，不做整行反白；悬停只加一层很淡的提亮。不需要给每行画键盘焦点环，焦点由列表容器统一处理。

## 交互与键盘

1. 点击设备行只改选中状态，不重建列表：正在处理事件的视图不销毁自己，避免按钮在鼠标按下与松开之间被替换，导致点击没有回调。
2. 列表重建只发生在搜索词变化、行数据变化、会话状态变化这些安全时机。
3. 点一下设备行会把键盘焦点交给列表：之后上下键移动、回车执行主要动作、直接输入就跳到搜索框。
4. 快捷键：⌘F 搜索、⌘J 回设备列表、⌘R 重扫、⌘L 日志、⌘. 断开会话、⌘0 显示窗口、⌘Q 退出；列表里 Esc 清空搜索，搜索框里 Esc 同样清空并立刻回到完整舰队列表。
5. 邀请点下后立即显示进行中（旋转指示 + 按钮文案），成功后自动打开观看窗口；失败时写明原因并保留日志入口。
6. 会话横幅只在真的处于会话时出现，和「服务器在线」明确区分；只在第一次出现时 0.18 秒淡入，其余不加动效。
7. 底部只有开机自启这一个显式开关和一行归属说明，关键动作不放在底部。

## 无障碍与自适应

- 设备行设置 `accessibilityRole` / `accessibilityLabel`，并支持辅助功能的「按下」操作。
- 文字使用系统语义色，按钮用系统控件，键盘焦点按 macOS 习惯走。
- 设备窗口最小 900 × 600，观看窗口最小 720 × 420；布局按内容重排，窗口变窄时先压缩状态列和提示文案。

## 观看窗口与软件遮挡层

- 观看窗口顶栏：左边是画质与显示器，右边是「端到端加密会话」和「断开」。画面区域在顶栏之下，顶栏不遮住远端画面的任何一行像素。
- 画面按远端分辨率等比缩放到视图内居中，多出来的部分留黑，不再把画面拉变形；鼠标坐标用同一个矩形反算，所以留边上的点击不会发到对面。会话中途对面换了显示器或改了分辨率时，比例和坐标换算会跟着刷新。
- 还没有能解码的画面时，画面区域明确写「等待远端画面…」，不给一块纯黑。
- 软件遮挡层：品牌深蓝底（取自图标底色）、产品名和一句实话——这是软件遮挡，不是硬件隐私屏，它挡不住截图或录屏。macOS 没有公开的虚拟显示器接口，只能做到这一步，所以必须如实告知。
- 遮挡是逐屏的：每块显示器一个无边框窗口。只盖主屏等于没盖，所以插拔显示器时会按新的屏幕集合重建。

## 还没有验证的部分

- 已通过 `cargo build -p jr-node`，但没有在真机点过：明暗外观切换、键盘与辅助功能实际行为、最小窗口与宽屏下的排版、会话横幅、日志窗口都还没有实测。
- 观看窗口的等比留边与逐屏遮挡（含插拔显示器后的重建）都还没有实机验证，包括鼠标在缩放后的位置上是否精准。
