# 06 平台适配器

每个平台在各自适配层内完成采集、编解码、窗口与注入（Windows 位于 `crates/jr-host-win`，macOS 位于 `apps/node/native/macos`），再结合 `jr-input` 与权限状态上报接入节点。协议层只看到 `Capability`，不暴露 Win32 或 AppKit 类型。

权限缺失时 host 仍然保持信令在线，`feature_bits` 里关掉对应能力，Presence 状态为需授权。不要因为没权限就退出进程。

## 1. Windows（被控与主控）

### 1.0 现在到哪一步

代码在 `crates/jr-host-win`。已经写好并通过编译与单元测试覆盖的模块：

| 部分 | 文件 | 做法 |
|---|---|---|
| 屏幕枚举 | `display.rs` | `EnumDisplayMonitors` + `GetDpiForMonitor`，主屏排第一 |
| 采集与零拷贝 | `capture.rs` / `d3d.rs` | DXGI 桌面复制 → `ID3D11VideoProcessor` GPU BGRA→NV12 零拷贝 → Media Foundation H.264；转换链失败回退 CPU 回读 |
| 编码与码流转换 | `capture.rs` / `h264.rs` | `MFTEnumEx` 优先硬编，支持运行中动态改码率/帧率；AVCC↔Annex-B 与色彩转换纯函数单测覆盖 |
| 系统音频 | `audio.rs` | WASAPI Loopback 采集 + Media Foundation AAC 编码与播放，带会话代次（generation）隔离 |
| 键鼠与触控注入 | `inject.rs` / `pointer.rs` | `SendInput` 扫描码映射 + `InitializeTouchInjection` / `InjectTouchInput` 触控注入 + 光标形状抓取 |
| 剪贴板 | `clipboard.rs` | `CF_UNICODETEXT`，读有上限，打开带有限重试 |
| 终端 | `conpty.rs` | `CreatePseudoConsole` + 属性列表挂到子进程，尺寸变化走 `ResizePseudoConsole` |
| 自启 | `autostart.rs` | 当前用户 `HKCU\...\Run`，不写 HKLM、不装系统服务 |
| 遮挡层 | `privacy.rs` | 置顶分层窗绘制明确提示文字，节点如实上报「软件遮挡」降级 |
| 设备窗口与托盘 | `desk.rs` | 设备列表、邀请/授权/撤回授权/撤销、授权弹窗、画质档、开机自启、系统托盘（含 `TaskbarCreated` 重挂与「恢复屏幕」） |
| 观看窗口 | `view.rs` | Media Foundation H.264 解码上屏、等比留边、远端光标 AlphaBlend 合成、键盘与滚轮输入、失焦自动释放按键 |

两段纯数据换算（AVCC 转 Annex-B、BGRA 转 NV12 / NV12 转 BGRA）放在 `h264.rs`，不碰系统。
设备行怎么拆也在 `desk.rs` 里，不碰系统，所以在任何平台都能跑测试。
**窗口和采集一次都没有在 Windows 机器上跑过。**

在 macOS 上能这样查类型：

```
# 适配器本身，只依赖 windows crate，绕开了 rustls 要 C 交叉编译器那件事
cargo check -p jr-host-win --target x86_64-pc-windows-msvc

# 整个节点：先 brew install mingw-w64，再 rustup target add x86_64-pc-windows-gnu
cargo check -p jr-node --target x86_64-pc-windows-gnu
```

谁第一次在真机上跑，谁负责把这一节的措辞改掉：写「跑过」之前先说清楚跑的是哪一版。

设备窗口和 macOS 一样是系统窗口，不是网页壳。列表按能力开关按钮：不能邀请的行不给「邀请」。已有无人值守授权时行尾显示状态，「撤回授权」才可用。画质四档和命令行 `quality 1-4` 同一套（清晰 / 均衡 / 高帧率 / 省流量）。「日志」用资源管理器打开日志目录。观看窗口写在 `view.rs`：顶栏有画质、显示器和断开，画面按远端分辨率等比留边，留边上的点击不发出去；收到 Annex-B 后用 Media Foundation H.264 解码成 NV12，再转 BGRA 上屏，远端光标按 AlphaBlend 合成。进程启动时声明 DPI 感知，采集和鼠标坐标统一用物理像素。**窗口、解码、DPI 缩放下的输入、键盘与滚轮注入都没有在 Windows 上打开过**，切显示器也可以走命令行 `display N`。授权弹窗建不起来时按拒绝处理，不会自动同意。

### 1.1 采集（已写成，未跑过）

使用 Desktop Duplication，绑定到选定显示器对应的输出。不要用 GDI `BitBlt` 当主路径。GDI 会把帧拷进 CPU，预算不够。

流程：

1. 枚举适配器和输出，得到 `display_id` 与矩形。
2. 对选定输出 `DuplicateOutput`。
3. `AcquireNextFrame(2ms)`。
4. 指针信息单独读出，送光标通道。画面纹理留在 GPU。
   macOS 和 Windows 都会抓光标形状；Windows 用 `GetFramePointerShape`，位置和可见性走
   `GetCursorPos` / `GetCursorInfo`。
5. 把纹理交给编码器输入，能用注册资源和零拷贝就用。做不到零拷贝时允许一次 GPU 内拷贝，不允许默认路径读回系统内存。
   当前默认路径是 `ID3D11VideoProcessor` 把 BGRA 转成 NV12，再通过 MF D3D 设备管理器
   直接交给编码器；转换链任一步失败才回退 CPU 回读。
6. `ReleaseFrame` 必须在下一帧等待前调用。泄漏释放会导致采集静默停住。

采集失败的常见原因要映射成状态，不要统一报“连接失败”：

| 现象 | 状态 |
|---|---|
| 访问被拒 | 需授权，或会话不在当前用户桌面 |
| 输出丢失、模式改变 | 重新枚举，发新 Capability |
| 安全桌面（UAC 安全提示） | 第一版不控制。画面冻结并告诉主控“对方正在系统安全提示，无法查看”。不安装服务去绕过 |
| 没有输出 | 若用户打开了虚拟屏功能，创建虚拟输出再采。否则状态为需授权/无显示器 |

### 1.2 编码

按优先级探测：NVENC、AMF、Quick Sync。都没有才软编，并在 Capability 的实现注释位告诉 UI。探测用编码器能力查询，不靠显卡品牌字符串。

参数意图见媒体文档。Windows 实现把这些意图写成一个函数 `apply_low_latency_profile`，禁止在业务代码里散落魔数。

清晰档请求 4:4:4 时，若能力查询没有该档次，静默退回 4:2:0，并在会话信息里写“此设备无法真彩”。不要硬开一个会失败的档次。

### 1.3 音频

WASAPI 回环模式，共享模式即可。格式转成 48 kHz 立体声再送系统 AAC 编码器（Media Foundation）。失败则本会话关闭 audio_out，画面继续。

### 1.4 输入

`SendInput`。绝对坐标用虚拟桌面的 0–65535 归一化时要自己换算对，协议里我们传的是物理像素加原点，适配器负责换成 `SendInput` 要的坐标系。这个换算要有单元测试，用假的双屏原点（例如第二屏 x=1920）验证点击落点。

相对移动在游戏模式使用 `MOUSEEVENTF_MOVE`，不带绝对标志。

键盘用扫描码 / HID usage 到 Windows 虚拟键的固定表，自己维护这张表，不调用一个远控库的映射。表覆盖字母、数字、修饰键、方向键、功能键和常用符号。表里没有的键忽略并计一次调试计数，不断会话。

500ms 抬起和会话结束抬起在这一层执行。

不注入到 Winlogon。第一版 host 跑在当前用户会话，不安装驱动。

### 1.5 虚拟显示器和隐私

虚拟显示器用 IddCx 间接显示驱动。驱动是我们自己的最小实现：报告一块显示器，帧缓冲给采集用。不从网上搬一个来路不明的驱动二进制放进仓库。

隐私模式：

1. 写恢复文件：当前启用的路径、哪块是物理屏。
2. 启用虚拟输出，把采集切到虚拟输出。
3. 关闭物理输出，或把物理输出设成不显示虚拟桌面的内容。
4. 主控连接的是虚拟输出上的桌面。

若驱动加载失败，拒绝隐私，原因 `privacy_unsupported`。会话可以继续，屏幕不黑。

恢复函数在普通断开、崩溃重启、热键三条路径调用同一份代码。

### 1.6 进程

节点是用户会话里的普通进程，不是内核驱动，也不是第一版的 Windows 服务。开机自启用用户的启动项，默认关。这样不会在登录前就采集。登录前控制是明确的非目标。

托盘图标在 `desk.rs` 里创建，和主窗口同线程；Explorer 重启后按 `TaskbarCreated`
重新挂图标。退出、刷新、断开会话和恢复屏幕都走托盘菜单。仍未实机验证。

## 2. macOS 被控

### 2.1 权限

两份权限都要，缺一不可：

- 屏幕录制：没有它就不能采集。
- 辅助功能：没有它就不能注入输入。

首次启动打开我们自己的向导，跳到系统设置对应页。用户授予后进程可能需要重启采集，向导要说这句话。不试图用私有 API 预授权。

权限状态用系统查询接口周期检查，每 2 秒一次就够。被用户中途关掉时，会话发送 Bye，原因 `permission_missing`，然后保持在线。

### 2.2 采集和编码

采集用 ScreenCaptureKit，选定 `display`。输出要 IOSurface，送给 VideoToolbox 硬编。不要用已废弃的 `CGDisplayStream` 当主路径。

编码意图与 Windows 相同。VideoToolbox 的实时和低延迟属性都要打开。B 帧关闭。

音频用系统回环需要的公开接口。若当前系统版本没有稳定的进程外回环，第一版可以关闭 macOS 的 audio_out，并在能力里声明没有声音。不要为了声音去加载内核扩展。画面验收不依赖声音。

### 2.3 输入

`CGEvent` 发布到 HID 事件源。同样做物理像素到全局坐标的换算测试。辅助功能未授予时，注入返回错误，不重试循环。

安全输入框我们不绕过。采到黑块就是黑块。

### 2.4 虚拟显示器和隐私

使用系统公开的虚拟显示器接口创建一块只用于采集的屏。物理屏不镜像它。接口在目标系统版本不可用时，隐私功能拒绝，Mac 被控的其余功能仍可用。

恢复路径和 Windows 同一套状态文件语义，路径放在应用支持目录。

### 2.5 进程

host 是用户代理，登录后启动，默认不启动。菜单栏图标由 host 持有。沙盒若和屏幕录制冲突，桌面被控进程不进 App Sandbox；分发时用开发者签名和公证，而不是削弱权限模型。签名是发布问题，不是协议问题。

## 3. Linux

### 3.1 第一版要交付的

无桌面：不开采集。Capability 只有 terminal 和 file。shell 用该用户的登录 shell，PTY 自己建。尺寸变化写 `TIOCSWINSZ`。

有桌面但不在 M7 后半：列表上显示在线，视频能力为 0，不要放一个必然失败的“控制桌面”按钮。

### 3.2 桌面阶段

采集优先用门户（用户点一次允许的那种），不先写一个绕过合成器的抓屏。门户拒绝就没有视频能力。

Wayland 下输入注入可能没有全局权限。做不到就关掉 input bit，保留 video，变成观看。X11 可以注入时再开 input。

不在第一版写内核模块。

## 4. Android 被控

采集和注入留在 Kotlin / Java，因为系统接口在那里。Rust 只接收已编码的 AAC/H.264 缓冲和要发出的输入事件描述。JNI 边界收成一个文件，不让协议类型泄漏成 Java 到处可见的复制品。JNI 上只传字节数组：已经是 JRP 内层 body，或还未打包的码流加上时间戳。

### 4.1 录屏

`MediaProjection` 必须由用户在系统对话框里同意。同意结果不能跨重启复用。进程被杀后同样失效。

前台服务类型包含媒体投影。通知文案固定为“正在允许被控”，停止按钮结束会话并停止采集。

没有通知渠道开关能把这条通知降成不可见。渠道重要性设为用户能看见。

### 4.2 编码

MediaCodec 硬编，异步回调。surface 输入，不从 CPU 读位图再编码。参数意图相同：无 B 帧，低延迟，CBR，每 2 秒 IDR。

### 4.3 输入

使用用户显式启用的无障碍服务注入手势和按键。启用页用我们的文字说明：这会允许舰队内已授权设备操作这部手机。不引导用户关闭系统的安全限制。

无障碍服务没有连接时，video 可以有，input 为 0。

不使用隐藏 API、不使用设备管理员去保活、不申请设备所有者。做不到开机即被控是规格，不是缺陷清单里的洞。

### 4.4 后台限制

系统杀进程后，信令断开，其他设备看到离线或需重新允许。不实现保活黑科技。所有者要手机被控时，手机应在前台服务已启动的状态。

## 5. 手机主控（Android 和 iOS）

两者都只实现解码、呈现、触摸采集、信令。

- 硬解 H.264。第一版不要求手机硬解 H.265，所以被控默认 H.264。
- 渲染用系统图形层，不用 WebView。
- 触摸默认映射成绝对坐标。双指拖动是滚轮。长按是右键。这是界面约定，事件仍用协议里的鼠标键和滚轮，避免被控端为手机单写一套。
- 游戏指针是会话里的开关，打开后触摸增量变成相对移动。
- iOS 工程里不编译被控适配器，连空实现都不要，避免以后有人接上。
- 手机进后台：若系统允许网络继续，会话可维持到心跳死亡；画面可以停。回到前台请求一次关键帧。不在后台继续注入，除非会话仍在前台服务里且用户看得见通知。iOS 进后台就停止发送输入。

## 6. 桌面主控窗口

原生窗口，不嵌 WebView。

窗口职责：

- 呈现最新帧和光标层。
- 采集键盘焦点和指针。
- 提供一层薄工具条：断开、画质、显示器、隐私、文件。工具条不经过网页。
- 全屏时隐藏工具条，热键唤出。

输入焦点不在这个窗口时，不发送键鼠。避免用户在主控本机打字打到被控机器上。

## 7. 权限状态到 Presence 的映射

适配器上报：

```text
enum HostBlocker {
  None,
  ScreenPermission,
  InputPermission,
  ProjectionConsent,    # Android
  NoDisplay,
  SecureDesktop,
}
```

节点进程把 blocker 映射成产品文档里的状态文案。新增 blocker 时要同时加文案，禁止显示原始枚举。

## 8. 平台测试最低集

每个适配器在对应系统上有一份手工清单，自动化能做的先做换算和状态机。

Windows 手工：双屏点击落点、拔掉一块屏、UAC 弹出时的提示、隐私开关和崩溃恢复、无显卡时的文案。

macOS 手工：拒绝屏幕录制、只给屏幕录制不给辅助功能、授予后重启采集、隐私不可用时的拒绝文案。

Android 手工：拒绝录屏对话框、划掉通知、重启手机后的状态、无障碍关闭时只能看不能点。

iOS 手工：只能当主控，后台时不再发送点击。
